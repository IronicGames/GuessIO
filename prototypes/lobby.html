UX / Design Notes — Lobby Prototype
Join Code in the Header
Hidden by default (shows ••••••) to prevent shoulder surfing — if your opponent can see your screen you don't want them to grab the code and share it. Click to reveal + auto-copy. The header is the right place: it's always visible regardless of which panel state you're in, no digging required.
Board Selection Privacy (Joiner Waiting State)
Per the design doc: before the host confirms a board, the joiner sees a waiting spinner and nothing else. This is intentional — you shouldn't be able to browse your opponent's full board library. The confirmed board is the first shared moment. The host's boards are their private collection.
Back to Board Selection (Host Only)
The ← back arrow in the character panel header is host-only. Clicking it resets: both ready states are cleared, the joiner drops back to the waiting state. The joiner gets a system chat message saying the host went back. This prevents confusion if the joiner is already ready.
Character Disable — Host Only
Only the host can click to disable characters. The joiner sees the same grid but cards have cursor: default and no hover scale effect. Disabled cards show grayscale + 0.4 opacity (matching GridCard's disabled prop) with an ✕ overlay. The joiner can see what's been disabled — both players share the same final character set.
Validity Counter and Ready Gate
A live "X/24+ enabled ✓/⚠" counter sits in the panel header. The host's Ready button is blocked (greyed out, cursor:not-allowed) until ≥24 characters are enabled. The joiner can always ready up — they don't control the board. This prevents a game starting with too few characters.
Settings — Casual Mode Interaction
When Casual is selected, the turn timer segment control is greyed out and forced to Off (it would make no sense with Casual Mode's honour-based free-form play). The joiner sees all settings read-only — they can see the settings but cannot change them. This matches the design doc's host privilege model.
Ready Flow and Game Starting Overlay
When both players are ready a full-screen "Game Starting!" overlay appears with a progress bar (~3s). Either player can still un-ready before the bar fills (future: add a cancel button). A system chat message is added too. After the bar, the overlay closes and states reset — in production this would transition to the game route.
Tag Filter + Search
Combined filter: tag chip narrows by type, search input narrows by name within those results. "All" resets both. Works for both host and joiner. In Tag Mode, this is especially useful for hosts deciding which characters to disable — filter by a tag, then remove less interesting ones.
Right Panel Layout (Settings → Players → Chat)
Deliberately stacked: settings at top (stable, reference), players in middle (social context, ready state), chat at bottom taking remaining flex space. Chat persisting from lobby into game means it should feel prominent but not dominant. The chat section grows to fill available space while the other two sections stay fixed-height.
Invalid Board Handling
Invalid boards (fewer than 24 characters) are visible in the board grid but at reduced opacity with a red "Invalid" badge and cursor:not-allowed. Clicking them does nothing. This lets the host see why they can't use a board without hiding it entirely. The "Confirm Board" button stays disabled if an invalid board is selected.
Reuse of Existing Components
ContentPaper → both main panels. GridCard (item variant) → board cards + character cards, exact same bg/border/hover/disabled values. GridContainer pattern → both grids with search. FormShell footer pattern → panel footer with action buttons. AppHeader → extended with join code pill in the center slot.
